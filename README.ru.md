# Gramless Support

Основан на [nessshon/support-bot](https://github.com/nessshon/support-bot) от Shon Ness
и адаптирован для Telegram Serverless. Оригинальное уведомление о лицензии MIT
сохранено в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

Поддержка пользователей через личные сообщения и темы форума, с выбором русского
или английского языка и рассылками для владельца. Всё работает на TGCloud;
пользователи и операторы взаимодействуют с ботом через Telegram.

## Возможности

- Выбор русского или английского языка при `/start`, сохранение выбора и `/language`.
- Один диалог и одна тема форума на числовой Telegram ID пользователя.
- Копирование медиа средствами Telegram в обе стороны с сохранением подписей и форматирования.
- Обновление профиля и названия темы, восстановление удалённых тем, закрытие и повторное открытие.
- `/information` (также `/info`), `/ban`, `/silent`, `/close` и `/id` в группе.
- `/source` со ссылкой на оригинальный проект; меню команд на двух языках.
- Подтверждения доставки, уведомления о редактировании личных сообщений и блокировке/разблокировке бота.
- Закрепление метаданных и уведомлений о тихом режиме при наличии прав; удаление служебных сообщений в связанных темах.
- При закрытии используется системное уведомление Telegram. Уведомления о закрытии
  и открытии сохраняются; уведомления о доступности бота не отправляются в закрытые диалоги.
- Новая тема начинается с объявления со ссылкой на пользователя и описанием команд
  в стиле оригинального бота, затем идут краткие сведения о контакте. `/information` показывает все данные.
- Необязательная проверяемая эмодзи-иконка темы и настраиваемый язык уведомлений для сотрудников.
- Рассылки владельца: черновики с медиа, HTTPS-кнопки, предпросмотр, подтверждение,
  снимок списка получателей, отмена, история, прогресс и продолжение отправки партиями.
- Уведомления о опубликованных релизах GitHub в отдельной теме обновлений.

Перед отправкой ответа проверяется, что оператор сейчас состоит в группе.
Административные команды доступны администраторам и владельцу группы. Сообщения
из посторонних групп, общей темы, несвязанных тем, от ботов и анонимных отправителей,
а также команды сотрудников не могут попасть пользователю как ответ поддержки.

## Требования и установка

- Node.js 24+ и npm для разработки; бот с включённым Telegram Serverless.
- Приватная супергруппа с включёнными темами и ботом-администратором.
- Права на управление темами и удаление сообщений; закрепление сообщений необязательно.

```sh
git clone https://github.com/gramless/support.git
cd support
npm ci
npm run check
npm test
```

Для работы не нужны npm-зависимости, Redis, Docker, polling, отдельный backend,
фоновые процессы, Mini App или веб-панель. CLI закреплён как зависимость для разработки.

## Настройка Telegram и развёртывание

Создайте бота через [@BotFather](https://t.me/BotFather), включите Serverless и
получите **токен доступа CLI** в Serverless → CLI Access. Он отличается от токена
Bot API. Добавьте бота в приватную супергруппу с темами. Все участники группы,
кроме ботов, считаются доверенными операторами. Администраторы получают обычные
сообщения группы даже при включённом режиме приватности бота. Анонимные ответы
сотрудников игнорируются.

Для нового развёртывания:

```sh
npx tgcloud login
npx tgcloud migrate --dry-run --local
npx tgcloud migrate --safe --local
npx tgcloud push
npx tgcloud migrate --dry-run
```

Сначала проверьте результат dry-run. `--safe` применяет только добавления в схему.
Миграция по локальной схеме перед развёртыванием предотвращает обращения обработчиков
к отсутствующим таблицам. У каждого бота своя база; создайте схему до начала работы поддержки.

Укажите свои ID вместо примеров:

```sh
npm run configure -- -1001234567890 --owner=123456789 --language=en
npm run setup:commands
npm run verify:cloud
npx tgcloud webhook
```

`--owner` даёт доступ к рассылкам пользователю с указанным числовым Telegram ID.
Перед установкой его меню команд владелец должен запустить бота. Если рассылки
не нужны, не указывайте `--owner`. Чтобы узнать ID группы, отправьте в ней `/id`.

Владельца, язык уведомлений для сотрудников и иконку темы можно менять отдельно:

```sh
npm run configure -- --owner=123456789 --language=ru
npm run configure -- --emoji=off
```

Для включения иконки укажите `--emoji=<custom-emoji-id>` из результата Telegram
`getForumTopicIconStickers`. При настройке ID сверяется с этим списком; храните его
как строку. Настройка группы проверяет её приватность, наличие тем и права бота.
Существующие связанные диалоги нельзя перенести в другую группу без проверенной
миграции; резервные записи без назначенной темы можно безопасно исправить.

В TGCloud 0.2.0 нет документированного API переменных окружения для runtime.
Настройки хранятся в `support_config`: `support_group_id`, `owner_id`,
`staff_language` (по умолчанию английский) и необязательный `topic_emoji_id`.
Файлы авторизации в `.tgcloud/` исключены из Git. Для CI используйте секрет
`TGCLOUD_TOKEN`. Публичного endpoint для настройки нет.

## Язык и управление диалогами

| Где | Ввод | Действие |
| --- | --- | --- |
| Личные сообщения | `/start` | Выбор языка при первом запуске, затем инструкция по обращению в поддержку |
| Личные сообщения | `/language` | Изменить сохранённый язык: русский или английский |
| Личные сообщения | `/source` | Авторство и ссылка на оригинальный проект |
| Личные сообщения | Обычное сообщение | Создать или найти тему, скопировать сообщение, обновить подтверждение |
| Тема | `/information`, `/info` | Профиль, ID, языки, время контактов, флаги и состояние |
| Тема | `/ban` | Включить или выключить блокировку входящих; ответы оператора остаются доступны |
| Тема | `/silent` | Включить или выключить запрет исходящих; сообщения пользователя продолжают поступать |
| Тема | `/close` | Закрыть диалог и тему; новое входящее сообщение откроет их снова |
| Группа | `/id` | Показать ID группы, не отправляя его пользователю |
| Личные сообщения владельца | `/newsletter` | Создать, просмотреть, отправить или продолжить рассылку |
| Личные сообщения владельца | `/cancel` | Удалить текущий неотправленный черновик |

`/start`, `/language` и `/source` не создают темы поддержки. Пользователь может
отправить вопрос без выбора языка: тогда используется язык его Telegram.
Сохранённый выбор не зависит от последующих изменений профиля. Все переводы
и описания команд находятся в `tgcloud/lib/i18n.js`. Ответы сотрудникам используют
выбранный ими язык или язык Telegram; метаданные и уведомления о состоянии — `staff_language`.

При редактировании личного сообщения бот просит отправить исправление новым
сообщением на языке пользователя. Изменённый текст повторно не копируется;
редактирование со стороны группы игнорируется. Подтверждения в личных сообщениях
обновляют одно сообщение вместо удаления по таймеру. Успешная отправка ответа
подтверждается временным сообщением Telegram, видимым только оператору; Telegram
не гарантирует его доставку получателям, которые находятся офлайн.

## Рассылки

Только настроенный владелец может создавать, просматривать, отменять и отправлять
рассылки. Выберите **Новую рассылку**, отправьте копируемый текст или медиа, затем
при необходимости добавьте кнопки: `Название | https://example.com`, по одной на
строку (до восьми), либо отправьте `/skip`. Проверьте предпросмотр перед нажатием
**Отправить сейчас**. До отправки содержимое можно заменить. Сохраняйте исходное
сообщение в чате владельца до завершения доставки.

При подтверждении фиксируется список подходящих зарегистрированных получателей.
Заблокированные пользователи, остановившие бота пользователи и сам владелец
исключаются; перед доставкой доступность проверяется снова. За одно нажатие
отправляется не более пяти сообщений. Нажимайте кнопку отправки следующей партии
до завершения. Состояние сохраняется между запусками; у владельца может быть
только одна активная рассылка. В истории отображаются последние десять записей;
отмена не удаляет запись.

**Выбор времени** сохраняет будущую дату в UTC. В отличие от планировщика оригинала,
автоматической отправки нет: в нужное время откройте `/newsletter` и нажмите
**Отправить сейчас**. В этом runtime TGCloud нет документированного таймера или
планировщика, и проект не запускает фоновые процессы. Время повторной попытки после
ограничения частоты запросов сохраняется. Прерванные отправки и отправки с неизвестным
результатом получают статус **uncertain**, а не повторяются вслепую. Прогресс отдельно
показывает доставленные, неудачные, неопределённые и ожидающие сообщения. Если
исходное сообщение отсутствует, отправка партии останавливается с явными ошибками.

## Уведомления о релизах

GitHub Action **Release updates** запускается только при публикации релиза в этом
репозитории и пропускает предварительные релизы. Он проверяет стабильные релизы
`gramless/support`. Если релиз новее установленной версии бота, Action создаёт
отдельную тему обновлений в настроенной группе поддержки и публикует установленную
и новую версии со ссылкой на описание релиза. Последующие уведомления используют
ту же тему; успешные объявления сохраняются, поэтому одна версия не публикуется
повторно. Установка необязательна и требует явного действия владельца;
миграции никогда не выполняются автоматически.

Для своего развёртывания создайте fork репозитория, включите GitHub Actions и
добавьте токен CLI бота в **секрет репозитория Actions `TGCLOUD_TOKEN`**.
Предварительно разверните бота и настройте группу поддержки. Без секрета workflow
пропускает проверку уведомлений. Не помещайте токен в файл workflow или Git-коммит.

```sh
npm run check:updates
```

Локальная команда использует сохранённые данные авторизации CLI. Она читает
`lib/version` из фактически развёрнутого снимка модулей, а не считает последний
локальный код уже установленным. Теги стабильных релизов должны иметь формат
`X.Y.Z` или `vX.Y.Z`. Черновики, предварительные релизы и отсутствие релизов
не вызывают уведомлений. Ежедневных проверок и ручного запуска workflow нет.
Fork не получает события публикации релизов оригинального репозитория: для проверки
обновлений используйте локальную команду или опубликуйте релиз в своём fork,
чтобы запустить его workflow.

Событие публикации релиза запускает короткий Action. Логика уведомлений использует только нативный SDK
и существующую базу; фонового процесса бота и публичного endpoint планирования нет.
В `support_config` сохраняются тема и группа обновлений, последняя объявленная
версия и временная блокировка параллельных проверок. Удалённая тема заменяется,
а закрытая открывается, когда нужно объявить новый релиз. Темы обращений
пользователей для этих уведомлений не используются.

### Обновление из Telegram

Кнопка **Обновить бота** меняет текст уведомления и показывает два варианта:
**Без компьютера** и **Команды CLI**, с кнопками возврата. Управление доступно
только настроенному владельцу Telegram. Вариант с телефона использует общее
[приложение Gramless Updates](https://github.com/apps/gramless-updates),
предназначенное для всех проектов Gramless, а не только Support.

В браузере телефона:

1. Используйте свой публичный репозиторий с workflow (создайте fork для своего
   бота), включите Actions и добавьте CLI-токен бота в секрет Actions `TGCLOUD_TOKEN`.
2. Отправьте `/updates владелец/репозиторий` в личном чате с ботом от настроенного владельца.
3. Установите Gramless Updates только на этот репозиторий. Права приложения:
   Actions write и Metadata read. Нажмите **Подключить GitHub** в инструкции.
4. Бот пришлёт код в личный чат. Введите его на странице устройства GitHub,
   нажмите **Проверить авторизацию**, затем вернитесь в **Без компьютера**
   и нажмите **Установить обновление**.

Personal access token, закрытый ключ приложения и client secret не нужны.
Авторизация временная: для следующего релиза при запросе подключитесь снова.
Обмен кода запрашивает доступ к ID выбранного репозитория. Каждый бот хранит
собственную привязку владельца и репозитория; одна установка не даёт доступа другим
ботам. Коды устройства и токены хранятся в приватной `support_config`, доступной
администраторам базы и CLI. Refresh-токены не сохраняются. Токен развёртывания
TGCloud остаётся в GitHub Actions.

Можно также открыть **Update bot** в браузере GitHub, нажать **Run workflow**,
указать тег релиза и оставить `request_id` пустым. Этот путь разрешён пользователям
с доступом на запись в репозиторий. Кнопка Telegram запускает тот же workflow
с сохранённым запросом; повторные нажатия не создают новое обновление. Оба пути
сообщают результат в тему после запуска скрипта развёртывания.

Вариант CLI показывает команды прямо в Telegram. Выбрать репозиторий с workflow
также можно из терминала:

```sh
npm run setup:updates -- gramless/support
```

Workflow получает точный коммит выбранного релиза, проверяет версию и изменения
схемы, затем развёртывает код с проверкой ожидаемой ревизии. Он отклоняет понижение
версии, удаление модулей и **любые необходимые изменения базы**: такие обновления
нужно проверить через CLI. Код официального релиза заменяет локальные доработки.
Если параллельное развёртывание изменило ревизию, workflow останавливается.

```sh
npm run setup:updates -- off
```

Команда удаляет сохранённую авторизацию GitHub; её также можно отозвать в настройках
приложений GitHub. При таймауте, ошибке до начала развёртывания или неизвестном
результате отправки сначала проверьте или отмените Action **Update bot** и уточните
установленную версию. Только убедившись, что в очереди и в работе нет запусков,
разблокируйте запрос командой `npm run setup:updates -- reset` и повторите попытку.
Не сбрасывайте активный запрос. Уже опубликованные уведомления при настройке
не изменяются: кнопка появится в уведомлении о следующем новом релизе.
Сначала установите обработчик обычным развёртыванием. Для других проектов
Gramless см. [заметки об общем приложении](docs/gramless-updates.md).
Приватные репозитории могут использовать браузер или CLI; этот device flow
получает ID выбранного репозитория из публичных метаданных.

## Хранение данных, безопасность и отличия платформы

`support_conversations` сохраняет существующие столбцы, ограничения и индексы,
добавляя только `silent_notice_id`. Таблица содержит маршрутизацию, профиль,
флаги, ID метаданных и время событий. `created_at` — первый контакт с поддержкой;
`last_in_at` учитывает обращения заблокированных пользователей, а `last_out_at`
меняется только после успешного ответа. Время хранится в UTC.

`support_users` хранит выбранный язык, доступность бота, ID сообщений интерфейса
и время регистрации. `support_newsletters` хранит ID исходных сообщений, кнопки
со ссылками, состояние, время отправки и повторных попыток, а также краткосрочную
блокировку партии. Записи получателей содержат состояние доставки. Байты медиа
и текст сообщений пользователей в эти таблицы не записываются. Метаданные
автоматически не удаляются; копии в Telegram подчиняются настройкам хранения чата.
`setup:commands` также регистрирует существующие диалоги, не заменяя их данные.

При первом обращении до вызова Telegram резервируется уникальный отрицательный
ID темы. Условное обновление закрепляет одну тему за диалогом; конкурирующие
вызовы удаляют свои неиспользованные темы. Маршрутизация разрешена только для
ID тем больше 1. Сохранено прежнее глобальное ограничение уникальности ID тем,
поэтому на одно развёртывание используйте одну группу поддержки. ID соответствуют
[52-битной гарантии Bot API](https://core.telegram.org/bots/api#user), хранятся
как SQLite INTEGER и проверяются на безопасное представление числом JavaScript.

Архитектура оригинала на Python/aiogram/Redis, ограничение частоты в памяти,
сборка альбомов, автоматическое планирование и удаление по таймеру адаптированы
к нативным обработчикам и постоянному состоянию. Элементы альбома копируются
по отдельности. ID ответов не переиспользуются между чатами. Неподдерживаемые
платные медиа, счета, розыгрыши и служебное содержимое не пересылаются. Исходные
личные обновления и ошибки не отправляются в чат разработчика.

Telegram и SQLite не могут выполнить общую атомарную транзакцию. Сбой при
закреплении темы может оставить временную несвязанную тему; повторная доставка
обновления поддержки может продублировать копию или повторить переключение флага.
Временные блокировки с токенами предотвращают параллельную отправку партий
рассылки; неопределённый статус получателя исключает автоматический повтор
прерванной доставки.

## Разработка и проверка

Runtime находится в `tgcloud/`. Рабочие обработчики: `message`, `callback_query`,
`edited_message` (только уведомление в личных сообщениях) и `my_chat_member`
(доступность бота). См. [справочник SDK](docs/tgcloud-sdk.md) и
[официальную документацию Serverless](https://core.telegram.org/bots/serverless).

```sh
npm run check
npm test
npx tgcloud push
npx tgcloud migrate --dry-run
npm run verify:cloud
```

`check` проверяет синтаксис, импорты и имена обработчиков. Тесты выполняют
производственный SQL и маршрутизацию на настоящей локальной SQLite с имитацией
транспорта Telegram: проверяют языки, принадлежность callback, гонки создания тем,
права, медиа, закрепления и восстановление рассылок. Отдельный линтер или проверка
типов не настроены. Облачные запуски без действий проверяют загрузку модулей;
`verify:cloud` проверяет реальные ограничения базы и права в группе. Служебные
скрипты используют внутренние API закреплённой версии CLI; проверяйте их при обновлении.
При подготовке релиза обновите версию и в `package.json`, и в
`tgcloud/lib/version.js`; `npm run check` проверяет их совпадение. После проверки
изменений и миграций опубликуйте соответствующий тег релиза GitHub. Каждый оператор
сам выбирает время развёртывания.

Работа с реальным трафиком Telegram не проверена. После настройки проверьте оба
языка, текст и медиа от двух пользователей, ответы операторов, `/information`,
блокировку и тихий режим, закрытие и открытие, удаление и восстановление темы,
закрепления, уведомления о редактировании, остановку и повторный запуск бота,
а также исключение анонимных сообщений. Для рассылок используйте отдельного
тестового бота и небольшую аудиторию, согласившуюся на тест; проверьте предпросмотр,
отправку, продолжение, отмену и прогресс. При валидации живая рассылка не отправлялась.
